## 1. overflow 成功路径不再标记 degraded
当前当 activeBuildCount > max-active-build-filter 时，会进入 ES bounded recall + PostgreSQL active validation，但 HybridRetrievalService 仍然加入 ACTIVE_BUILD_FILTER_LIMIT degraded。

改为：
- overflow 本身不是 degraded
- small-scope terms-filter 和 large-scope active-validation 都是正常路径
- 只有达到 MAX_OVERFLOW_PAGES / MAX_OVERFLOW_CANDIDATES 后仍不足请求 topK，才记录 ACTIVE_BUILD_VALIDATION_TRUNCATED 或等价状态

主要文件：
- modelrag-search/src/main/java/com/modelrag/search/orchestrator/HybridRetrievalService.java
- modelrag-search/src/main/java/com/modelrag/search/channel/v2/ElasticsearchRetrievalUnitSearch.java
- modelrag-search/src/main/java/com/modelrag/search/channel/v2/LexicalSearchPort.java

测试：
- G5V2RetrievalTest
- G5LexicalRetrievalTest

## 2. Benchmark correctness 不允许硬编码
RetrievalBenchmarkController 当前的 aclLeakage=false、activeBuildTruncated=false 不能作为真实证据。

### Active Build Sentinel
在 full benchmark 最后一个 active build/document 加明确 sentinel：
`G11_ACTIVE_BUILD_SENTINEL_<buildId>`

high-active-build-count workload 专门查询最后一个 >10000 build 的 sentinel：
- 找不到 -> activeBuildTruncated=true
- 找到 -> false

### stale validation
final candidates 再通过 RetrievalUnitRepository.findActiveByIds 做批量 active 校验。非 active candidate 计入 staleCandidateCount。

### evidenceValid
必须根据真实 active repository 结果验证 dataset/document/version/node/unit/build 身份，不能只判断 ID > 0。

涉及：
- benchmarks/retrieval-scale/generate/generate_dataset.py
- benchmarks/retrieval-scale/load/load_all.py
- benchmarks/retrieval-scale/workloads/workloads.json
- modelrag-server/src/main/java/com/modelrag/server/benchmark/RetrievalBenchmarkController.java
- benchmarks/retrieval-scale/run/benchmark.py

## 3. ACL 使用真实 Integration Test
Benchmark internal endpoint 本身不能证明 ACL。

新增真实 ACL 测试：
- User A 可访问 Dataset A
- User A 访问 Dataset B -> denied / 403

不要用 Benchmark Controller 的硬编码字段，也不要用 ENV boolean 伪造 ACL 证据。

## 4. ERROR 与 REFUSED 完全分离
JdbcRetrievalTraceSink.fail() 改为：
- status=ERROR
- refused=false

业务证据不足才是：
- status=REFUSED
- refused=true

修改：
- modelrag-common/src/main/java/com/modelrag/common/observability/JdbcRetrievalTraceSink.java

## 5. Category Gate 同时检查样本数和有效标注
不能只检查 category sample count。

至少要求：
- sample count >= minCategorySamples
- 对应核心 metric status != INSUFFICIENT_LABELS
- 对应核心 metric status != INSUFFICIENT_SAMPLE

建议映射：
- POINT_FACT -> documentRecallAt20
- CROSS_SECTION -> nodeRecall 或 documentRecallAt20
- CROSS_DOCUMENT -> completeEvidenceRecall
- MULTI_HOP -> completeEvidenceRecall
- TABLE -> nodeRecall / completeEvidenceRecall
- VERSION_SENSITIVE -> documentRecallAt20 + completeEvidenceRecall
- REFERENCE -> completeEvidenceRecall
- REFUSAL -> refusalAccuracy

修改：
- CutoverReadinessEvaluator.java
- EvaluationRunner.java

## 6. Benchmark 报告记录真实 Server JVM 版本
RetrievalBenchmarkController 返回：
`System.getProperty("java.version")`

Runner 写入：
- runtime.serverJavaVersion
- runtime.runnerJavaVersion（如果仍保留本地 java -version）

## 7. Full Benchmark 规则
只有真实满足以下条件才允许 status=COMPLETED + mode=full：
- >= 1,000,000 active RetrievalUnit
- >= 20,000 active Document
- > 10,000 active IndexBuild
- 1024-d vectors
- stale units
- PG + ES real data
- 全部 workloads
- concurrency 1 / 8 / 32

资源不足就输出 NOT RUN，并保持 NOT_READY_FOR_G12。
