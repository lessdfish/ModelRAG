## 6. Full 阻断与失败证据

### HNSW rebuild 过程

1. 2GB/4 workers 首次尝试受 Docker 默认共享内存限制失败：`could not resize shared memory segment ... No space left on device`；未生成索引。
2. 串行 512MB/2GB 能运行，但实测在约 448k tuples 后图落盘，速度降至不可接受的约 1–2 tuples/s。
3. 根据实测图大小，停止并保留旧容器，用同一专用 bind-mounted 数据目录启动有界配置：6GB `/dev/shm`、5GB maintenance memory、4 workers。
4. 最终构建扫描完全部 14,429 blocks，进度到 1,009,935 tuples，并开始将约 7.7GB HNSW 页面写入 F:。
5. 最终 flush 期间底层存储返回 I/O error，PostgreSQL 异常退出。关键日志：

```text
WARNING: could not write block 657718 of base/16384/1027698
DETAIL: Multiple failures --- write error might be permanent.
ERROR: could not open file "base/16384/1027698": Input/output error
PANIC: could not write to log file ...: Input/output error
```

Docker/主机恢复后 PostgreSQL 完成 crash recovery。只读核验结果：

- `kb_retrieval_unit = 1,010,000`
- `kb_vector_embedding = 1,010,000`
- active units = 1,000,000
- stale units = 10,000
- active documents/builds = 20,001 / 20,001
- sentinel row = 1
- Flyway = V66
- `idx_vector_embedding_hnsw = 0`

因此数据 load 成功，但 Full ANN 前置索引未完成。失败容器已停止，数据与容器均保留，没有删除用户数据或已有容器。
