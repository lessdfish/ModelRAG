# ModelRAG 2.0 G9 — Tool Gateway Extraction

## 2.0.22 Tool Gateway

> Target runtime: Java 21  
> Base commit reviewed: `59edf3279e73cfd7d364b140d67926df763e1a69`  
> Prerequisite: G8.1 accepted  
> Scope: extract business-tool capability from `modelrag-agent` into a dedicated Java control-plane module  
> Architecture style: **modular monolith**, NOT a new remote microservice  
> Flyway: **no new migration expected**  
> Do not start G10 / Python AI Compute Plane

---

# 1. Goal

After G8.1 the Agent side is structurally sound:

```text
Request
  ↓
AgentOrchestrator
  ↓
AgentRuntime
  ↓
AgentState / Checkpoint / Lease
  ↓
ToolAgentModeHandler
  ↓
ToolRegistry
ResilientToolExecutor
HttpToolInvoker
ToolCallTracer
```

The remaining problem is module ownership.

Today the business-tool subsystem still physically lives inside:

```text
modelrag-agent
```

even though most of it is not Agent reasoning/state logic.

Classes such as:

```text
ToolRegistry
ToolDefinition
ToolSecretCipher
ToolCallValidator
ToolCoordinationStore
RedisToolCoordinationStore
ResilientToolExecutor
HttpToolInvoker
ToolCallTracer
```

are infrastructure for **safe business-tool execution**, not Agent planning.

G9 changes the boundary to:

```text
modelrag-agent
    ↓
Tool Gateway public contracts
    ↓
modelrag-tool-gateway
    ↓
HTTP / INTERNAL tool adapters
    ↓
Business systems
```

Hard invariant:

> AgentRuntime decides *when* an approved action may execute. Tool Gateway decides *whether and how* that tool invocation is safely executed.

And:

> Tool Gateway must never depend on `modelrag-agent`, `modelrag-qa`, retrieval code, AgentState, LLM policy, or approval workflow.

# 2. G8.1 review gate

G8.1 is accepted for the current baseline.

Verified:

- durable Agent policy now receives bounded current Evidence text through `AgentPolicyInput.evidence`;
- Evidence context survives checkpoint codec round-trip;
- distributed cancellation no longer concludes global inactivity from the local Thread map;
- PostgreSQL now owns `CANCEL_REQUESTED -> CANCELLED` finalization based on lease state;
- stale cancellation finalization is bounded;
- real HTTP idempotency replay is tested with the same persisted `Idempotency-Key`;
- real non-idempotent recovery is blocked before external execution;
- absolute deadline survives restart;
- Agent budgets survive restart;
- live lease exclusion / expired takeover are tested;
- terminal duplicate execution reuses persisted result;
- RESUME / CHECKPOINT safe trace metadata exists;
- a shared lease heartbeat protects long-running policy/action calls;
- normal production routing defaults to no legacy non-durable fallback.

Do not regress any of these guarantees.

# 8. Do not merely move packages

G9 is a boundary extraction, not a `git mv` exercise.

Current `ToolDefinition` contains:

```text
authHeaderValue
```

and current `ToolRegistry.get/list()` returns decrypted values.

That means an object passed to planner/agent/admin code can carry a live credential even if it is not intentionally rendered.

G9 must separate:

```text
safe tool metadata
```

from:

```text
secret-bearing execution configuration
```
