## 1. Goal

G6 already gives us:

```text
Query
-> HybridRetrievalService
-> RetrievalCandidate
-> Evidence
-> bounded navigation
-> EvidenceSet
-> AnswerSynthesizer
```

The current Agent is still first-generation:

```text
AgentPlanner
-> knowledge_lookup
-> qa.answer(...)
-> QaResult
-> generated sub-answer becomes observation
-> repeat
-> combine generated answers
```

G7 must change the knowledge Agent path to:

```text
Goal
-> LlmAgentPolicy
-> read-only Retrieval Action
-> structured RetrievalObservation
-> Evidence accumulation
-> policy again
-> FINISH
-> EvidenceSelector
-> EvidenceSufficiencyPolicy
-> exactly one AnswerSynthesizer call
```

Core invariant:

> Retrieval tools return structured search/node/evidence observations, never `QaResult`.

> LLM decides an allowed action; Java enforces ID scope, dataset scope, budgets, limits and safety.

Target:


Simple knowledge question:



## 10. Deterministic capability guard

Critical invariant:

After initial search, source-specific actions may only use IDs already observed by this execution.

Allowed:

```text
SEARCH_KNOWLEDGE("annual leave")
-> returns nodeId=55 documentId=23

OPEN_NODE(55)       allowed
READ_PARENT(55)     allowed
FIND_IN_DOCUMENT(23,"approval") allowed
```

Rejected:

```text
OPEN_NODE(999999)
```

if node `999999` has never appeared in observations.

The model cannot guess arbitrary DB IDs.

Java enforces this.

Prompt text is not the security boundary.

## 23. Deterministic policy fallback

When:

```text
no configured user model
model error
timeout
invalid JSON
invalid action
```

use deterministic bounded policy.

Recommended:

```text
step 0:
SEARCH_KNOWLEDGE(original query)

then:
if EvidenceSufficiency == sufficient
    FINISH

else:
READ_NEIGHBORS(highest-ranked node)

then if useful:
FIND_IN_DOCUMENT(observed document, unresolved query)

otherwise:
FINISH
```

Do NOT fallback to:

```text
qa.answer(subtask)
```
