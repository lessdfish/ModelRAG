# ModelRAG G7.1 — Agentic Retrieval Stabilization

> Java 21  
> Base commit: `337009c33c93ce98794396214a647e12bffa9d4e`  
> Purpose: close G7 blockers before G8 durable AgentState/checkpoint work  
> No Flyway migration. Do not start G8.

## Review result

G7 is structurally close to the target, but it should not be closed yet.

Already correct and must be preserved:

- `DIRECT_RAG / AGENTIC_RAG / TOOL_AGENT` exist.
- Retrieval actions return structured Observation/Evidence, not `QaResult`.
- `SEARCH_KNOWLEDGE` uses V2 retrieval.
- `OPEN_NODE / PARENT / NEIGHBORS / CHILDREN / REFERENCES` are bounded.
- source-specific actions require previously observed IDs.
- `FIND_IN_DOCUMENT` uses `modelrag-retrieval-units-v2` plus active IndexBuild validation.
- `LlmAgentPolicy` uses strict JSON and deterministic fallback.
- AGENTIC_RAG has no `HttpToolInvoker` dependency.
- final answer is synthesized from `EvidenceSet`.
- G6 Citation and trace-persistence fixes are present.

The following issues are blocking G8.

---

## P0-1 — TOOL_AGENT must never fall back to `knowledge_lookup`

Current `AgentOrchestrator` still effectively does:

```text
TOOL_AGENT
  ├─ locked TOOL intent -> target tool
  ├─ high risk -> destructive_operation
  └─ otherwise -> knowledge_lookup
```

This breaks the three-mode boundary.

Example:

```text
"查询订单"
-> ComplexityRouter = TOOL_AGENT
-> no TOOL intent target
-> not high risk
-> knowledge_lookup
-> legacy QA path
```

Target behavior:

```text
TOOL intent with targetId
-> exact concrete tool

high-risk compatibility operation
-> destructive_operation only if existing approval/OperationGuard semantics remain

otherwise
-> fail closed: tool-unresolved
```

Never use `knowledge_lookup` as the generic TOOL_AGENT fallback.

`knowledge_lookup` may remain registered for backward compatibility, but the new TOOL_AGENT path must not silently execute it.

Required tests:

1. `"查询订单"` routes `TOOL_AGENT`.
2. Without a concrete mapped business tool:
   - `knowledge_lookup` is never executed;
   - `QaOrchestrator.answer()` is never used as tool fallback;
   - no arbitrary HTTP tool is selected;
   - result fails closed with `tool-unresolved`.
3. `IntentNode(targetType=TOOL,targetId=...)` still executes the mapped tool.
4. HIGH / EXTERNAL_SIDE_EFFECT tools still require approval.

---

## P0-2 — Agentic RAG must not terminate before policy sees retrieved evidence

Current `AgenticRetrievalOrchestrator` computes sufficiency and immediately breaks when it is true, before the next `LlmAgentPolicy.decide(...)`.

That can collapse AGENTIC_RAG into:

```text
SEARCH_KNOWLEDGE
-> two nodes returned
-> deterministic sufficiency=true
-> stop
-> synthesize
```

so the policy never gets a chance to choose:

```text
READ_NEIGHBORS
OPEN_NODE
FIND_IN_DOCUMENT
FOLLOW_REFERENCES
second SEARCH_KNOWLEDGE
```

Target loop:

```text
selected Evidence
-> compute EvidenceSufficiency
-> build AgentPolicyInput including sufficiency
-> LlmAgentPolicy decides ACTION or FINISH
```

Do not unconditionally `break` merely because sufficiency is currently true.

The deterministic no-model fallback may still return `FINISH` immediately when sufficient, so cheap fallback behavior remains.

Final Java gate remains authoritative:

```text
final insufficient EvidenceSet -> 0 synthesis calls
final sufficient EvidenceSet   -> exactly 1 synthesis call
```

Required multi-step test:

```text
SEARCH_KNOWLEDGE
-> evidence becomes potentially sufficient
-> configured policy requests READ_NEIGHBORS or second SEARCH
-> action really executes
-> policy FINISH
-> exactly one final synthesis
```

Also verify no-user-model fallback can FINISH immediately when sufficient.

## P0-3 — SEARCH_KNOWLEDGE must not accidentally bypass dataset threshold

`QaV2ApplicationService` passes `dataset.threshold()` into `RetrievalV2Request`.

Current `SearchKnowledgeAction` passes:

```text
threshold = 0
```

Combined with default Evidence minimum score 0, weak search hits can become sufficient too easily.

Smallest safe fix:

```text
SearchKnowledgeAction
+ DatasetRepository
```

Then:

```java
Dataset dataset = datasets.findById(context.datasetId());

new RetrievalV2Request(
    context.datasetId(),
    query,
    limit,
    dataset.threshold(),
    embeddingProfiles.profile()
);
```

Add a test proving a non-zero dataset threshold, e.g. `0.73`, reaches the V2 retrieval request.

If actual score semantics make this incompatible, stop and report instead of inventing a second score calibration.

## P1 — Per-action trace/SSE visibility

The outer `AgentOrchestrator` currently emits initial/final events, while the dedicated Agentic loop does not expose each retrieval action through the existing trace/SSE boundary.

Before durable AgentState, each action should emit safe bounded lifecycle events:

```text
PLAN
ACT
OBSERVE
```

Suggested event payloads:

```text
PLAN:
step, action, remaining budgets

ACT:
action, safe parameter summary

OBSERVE:
action, itemCount, newEvidenceCount, latencyMs, degradedComponents
```

Do not emit full evidence bodies, full prompts, chain-of-thought, or secrets.

Preferred design: a tiny callback such as:

```java
interface AgenticRetrievalEventSink {
    void publish(String type, String message, Map<String,Object> data);
}
```

`AgentOrchestrator` adapts it to its existing `publish(...)`, keeping `AgentStepTracer + SSE` authoritative.

Add a two-action test verifying ordered action events.

---

## P1 — Preserve policy JSON rules when prompt context is full

`LlmAgentPolicy.promptFor(...)` appends output-format rules at the end and then truncates the whole prompt.

If observations fill the budget, the final JSON contract can disappear.

Reserve space for immutable rules:

```text
header/rules
+ bounded observation section
+ final ACTION/FINISH schema
```

Truncate observations first.

A near-limit test must still find:

```text
ACTION
FINISH
JSON only
no reasoning
```

in the final prompt.

## Optional semantic cleanup

`OpenNodeAction` currently labels opened-node structural evidence as `EvidenceOrigin.REFERENCE`.

Opening an observed node is not reference traversal.

Prefer adding a neutral `OPEN` origin or another clearly documented non-reference origin.

This is optional and needs no migration.

6. deterministic fallback can still FINISH immediately when sufficient.
7. final Java EvidenceSufficiency remains authoritative.
8. SEARCH_KNOWLEDGE uses dataset retrieval threshold.
9. per-action PLAN/ACT/OBSERVE events are bounded and safe.
10. policy JSON rules survive near-limit observation context.
11. a real multi-step Agentic Retrieval test passes.
12. sufficient final set => exactly one synthesis.
13. insufficient final set => zero synthesis.
14. no AgentState/checkpoint/resume work starts.
15. no Flyway migration is added.
16. full Maven tests pass.
