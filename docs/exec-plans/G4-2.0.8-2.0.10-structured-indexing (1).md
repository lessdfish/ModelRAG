# ModelRAG 2.0 G4 - Structured Ingestion & Dual Write

## Scope

- `2.0.8 Structured Parser`
- `2.0.9 IndexingPipeline decomposition`
- `2.0.10 Dual-write V1/V2`
- Runtime: Java 21
- Prerequisite: G3 / V57-V59 merged and green
- Strategy: additive migration; V1 remains the production read path

---

# 1. Goal

G3 has established the V2 model:

```text
Document
  ├─ activeVersionId -> DocumentVersion -> DocumentNode -> RetrievalUnit
  └─ activeIndexBuildId -> IndexBuild -> VectorEmbedding
```

But real ingestion still follows the legacy chunk path:

```text
DocumentUploadedEvent
  -> IndexingPipeline
  -> artifact.txt
  -> RecursiveCharSplitter
  -> Chunk
  -> kb_chunk.embedding
  -> UPSERT_CHUNK
  -> Elasticsearch
```

G4 is the first batch where uploaded documents must also produce the real V2 structure:

```text
DocumentUploadedEvent
        |
        v
IndexingPipeline facade
   |                |
   v                v
Legacy V1      V2 IndexBuildCoordinator
   |                |
   |                +-> DocumentParseStage
   |                +-> StructurePersistStage
   |                +-> RetrievalUnitBuildStage
   |                +-> EmbeddingStage
   |                +-> VectorProjectionStage
   |                +-> LexicalProjectionStage
   |                +-> Verification / Activation
   v
current production search
```

Critical rule:

> G4 is dual-write, not cutover.

Current online retrieval remains V1.

# 3. Important migration decision

Do not replace the current upload parser path in G4.

Current upload already stores:

```text
source object
+
normalized artifact.txt
+
DocumentVersion
```

V1 depends on `artifact.txt`.

V2 structured parsing should read the immutable original source referenced by the active `DocumentVersion`:

```text
upload
  ├─ artifact.txt    -> V1
  └─ source object   -> V2 Structured Parser
```

This intentionally causes an additional parse only when V2 structure is first created.

Once `DocumentNode` exists for the immutable `DocumentVersion`, later `IndexBuild`s reuse the same tree.

Do not reparse the same version simply because embedding/retrieval policy changes.

# 10. StructurePersistStage

Add:

```text
StructurePersistStage
```

Responsibilities:

```text
ParsedNode.localId
  -> DocumentNode.id

parentLocalId
  -> parent database id

ParsedEdge
  -> NodeEdge
```

Persist nodes topologically:

```text
depth ASC
ordinal ASC
```

Then persist explicit edges.

Validate before commit:

```text
exactly one DOCUMENT root
all parents exist
depth = parent.depth + 1
sibling ordinal valid
edge endpoints valid
all IDs belong to the build document/version/dataset
```

Concurrency rule:

```text
parse outside TX
  -> lock DocumentVersion/document row
  -> recheck structure existence
  -> persist only if still absent
```

Two workers must not create two trees for one `DocumentVersion`.

If another worker wins while parsing, reuse the persisted tree.

# 28. IndexBuildCompletionWorker

Add a bounded scheduled worker.

For builds in:

```text

```

check V2 outbox state.

If any row is terminal FAILED:

```text

```

If all expected rows are DONE:

```text
LEXICAL_SYNCING
  -> VERIFYING
  -> IndexVerificationStage
  -> READY
  -> IndexBuildLifecycleService.activateBuild
  -> ACTIVE
```

Extend `IndexBuildRepository` only with the bounded state query required by this worker, e.g.:


Do not add `findAllBuilds()`.

# 29. Verification rules

Before READY require:

```text
build.documentVersionId == document.activeVersionId

nodeCount > 0
unitCount > 0

unitCount == RetrievalUnitRepository.countByBuild(buildId)

vectorCount == RetrievalEmbeddingRepository.countByBuild(buildId)

lexicalCount == DONE V2 outbox count

lexicalCount == unitCount
```

Use repository-derived final counts rather than blind retry increments.

Do not use an LLM as build verifier.

# 31. Dual-write facade semantics

Recommended `IndexingPipeline.index(documentId)` behavior:

```text
1. run LegacyChunkIndexingPipeline

2. if V1 failed:
     preserve current production failure behavior
     do not pretend V2 success makes production healthy

3. if V1 succeeded and V2 shadow is enabled:
     start IndexBuildCoordinator

4. if V2 fails:
     build -> FAILED
     log/metric/SSE shadow failure
     do NOT roll back successful V1
```

Core rule:

> V2 shadow failure must never break successful V1 serving.

Dual-write is not a distributed transaction.

Rollback safety comes from independent V1 index versioning and V2 IndexBuild activation.

# 34. Failure behavior

Any synchronous V2 stage exception:

```text
IndexBuildLifecycleService.fail(buildId, SafeErrorSummary.of(error))
```

Do not modify the previous active build pointer.

A hard JVM crash may leave a build in a non-terminal stage.

G4 does not need a full durable workflow engine, but incomplete builds must never be interpreted as READY.

Optional bounded stale-build sweeper may mark abandoned builds FAILED after timeout.

Do not implement full resume/checkpoint semantics in G4.

# 35. Required integration scenarios

## Dual-write success

One indexing request produces:

```text
V1:
  kb_chunk
  kb_chunk.embedding
  legacy ES projection
  active_index_version

V2:
  kb_document_node
  kb_retrieval_unit
  kb_vector_embedding

```

Current `SearchOrchestrator` still reads V1 only.

## V2 failure isolation

Simulate:

```text
V1 succeeds
V2 embedding or V2 ES fails
```

Verify:

```text
legacy active_index_version remains valid
legacy chunks remain usable
V2 build = FAILED
active_index_build_id remains previous value / NULL
```

## Structure reuse

```text
DocumentVersion 1
Build 1 -> creates nodes
Build 2 -> reuses nodes, creates new RetrievalUnits
```

No duplicate root/tree.

## Stale content race

```text
Version 1 build starts
Version 2 becomes active
Version 1 finishes
```

Version 1 build activation must be rejected.

# 41. Final acceptance criteria

G4 is complete only when:

### Structured Parser

1. additive `StructuredDocumentParser` exists.
2. legacy `DocumentParser` remains functional.
3. MD heading hierarchy is preserved.
4. DOCX heading/list/table structure is preserved.
5. PDF page locators survive.
6. no-text PDF still returns OCR_REQUIRED.
7. TXT parsing is conservative.
8. parsed nodes use local IDs.
9. exactly one root exists.
10. parent/depth/ordinal integrity is validated.
11. parsing remains bounded and timeout-protected.

### Structure persistence

12. DocumentNodes belong to DocumentVersion.
13. second IndexBuild reuses nodes.
14. concurrent workers cannot create duplicate trees.
15. parsing is outside the persistence transaction.

### Pipeline decomposition

16. `IndexingPipeline` is a facade.
17. V1 logic is extracted with no semantic regression.
18. `IndexBuildCoordinator` owns V2 orchestration.
19. remote embeddings are outside DB transactions.
20. each V2 stage has a narrow responsibility.

### Retrieval units / vectors

21. real DocumentNodes generate RetrievalUnits.
22. oversized nodes split only at projection time.
23. unit generation is bounded.
24. titlePath is deterministic.
25. contentHash reflects retrieval text.
26. vectors persist to `kb_vector_embedding`.
27. legacy `PostgresVectorStore` remains V1-only.

### V2 lexical projection

28. V60 creates dedicated V2 outbox.
29. V2 does not overload legacy `chunk_id`.
30. V2 outbox supports lease/retry/idempotency.
31. V2 ES uses one shared `modelrag-retrieval-units-v2` index.
32. no one-index-per-build design is introduced.
33. `modelrag-chunks-active` is untouched.
34. V2 lexical projection is asynchronous.
35. completion worker only finalizes complete builds.

### Verification / activation

36. node/unit/vector/lexical counts are checked.
37. incomplete build cannot become READY.
38. stale version build cannot activate.
39. READY -> ACTIVE reuses G3 atomic activation.
40. activation performs no mass unit/vector/ES update.
41. legacy `active_index_version` is untouched.

### Dual write

42. one indexing operation can create both V1 and V2 projections.
43. V1 remains production read path.
44. V2 failure does not roll back successful V1.
45. V1 failure is not hidden by V2 success.
46. feature flag can disable V2 shadow build.
47. SearchOrchestrator remains unchanged.
48. no Evidence/Agent/Python work starts.
49. V1-V59 remain immutable.
50. all affected tests pass.
