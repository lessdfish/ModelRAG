# ModelRAG 2.0 — G11.8 Evidence Freeze + Full 1M Benchmark

## 目标

G11.7 已完成 20k Smoke，结果为 `SMOKE PASS`。当前阻塞点不是性能代码，而是这些结果来自 dirty working tree，报告中的 commit 仍是旧基线，尚不能作为最终可复现证据。

本轮只做四件事：冻结 G11.4–G11.7 的有效修改并创建本地正式 commit；在 clean commit 上重新跑同规格 20k Smoke；Smoke 再次 PASS 后执行 Full 1M Benchmark；最后用 commit-bound evidence 执行 G11 readiness gate。不进入 G12。

## 1. Freeze 前检查

先执行：

```powershell
git status --short
git diff --stat
git diff
git rev-parse HEAD
mvn -v
java -version
```

要求 Maven/Runtime 均为 Java 21。

逐项审查当前 G11.4–G11.7 修改，只保留确实属于检索、诊断、ANN-first、DB cancellation、executor capacity、benchmark 与相关测试/配置的内容。

不要提交：

```text
临时 Ollama bridge
本机路径文件
target/
IDE 文件
临时日志
旧 Smoke report / 临时 benchmark 输出
其他无关 untracked 文件
```

如果发现来源不明或无法确认用途的修改，不要删除，先列出并停止提交。

## 2. 创建正式本地 Commit

确认 diff、模块测试和 Python benchmark tests 均通过后，创建一个本地 stabilization commit，建议 message：

```text
feature 2.1.7
```

不要 push。

提交后执行：

```powershell
git status --short
git rev-parse HEAD
```

用于 Benchmark 的源码 working tree 必须 clean。仅允许保留不会影响源码 commit identity 的已知本地执行产物，并在报告中列明。

## 3. Commit-bound 20k Smoke

在新 commit 上重新跑与 G11.7 相同的 Smoke：

```text
20,000 active RetrievalUnit
```

必须验证：

```text

degradedRate == 0

noStaleBuildLeakage == true
sentinelRecall == true
activeBuildTruncationStatus == NOT_APPLICABLE
boundedResults == true
validEvidence == true
invalidEvidenceCount == 0
```

Smoke FAIL 就停止，不跑 Full。

## 4. Full 1M Benchmark

只有 commit-bound Smoke PASS 后才执行 Full。

Full fixture 必须满足现有 Full profile 的真实规模与 gate，重点确认：

```text
1,000,000 active RetrievalUnit
activeBuildCount > activeBuildFilterLimit
真正进入 >10k active build overflow path
包含 stale build 数据
1024d
PostgreSQL/pgvector + Elasticsearch
Java 21
真实 embedding runtime
```

不要降低 Full profile 的规模、并发、workload 或请求数。

Full 必须验证：

```text
noStaleBuildLeakage == true
sentinelRecall == true
activeBuildTruncationStatus == PASS
boundedResults == true
validEvidence == true
invalidEvidenceCount == 0
```

同时记录整体和各 workload 的 p50/p95/p99、errorRate、timeoutRate、degradedRate，以及 Semantic/Lexical diagnostics、ANN refill、DB statement timeout、admission timeout、rejection count。

Full report 的 `gitCommit`、`serverJavaVersion`、fixture/profile 必须与正式 commit 和 Java 21 一致。

## 5. Readiness Gate

Full 完成后执行现有 G11 readiness/evaluation 流程，不修改 gate 来迁就结果。

重点检查：

```text
ACL evidence commit matches
Benchmark evidence commit matches
Server Java 21
No ACL leakage
No stale build leakage
No active-build truncation
Evaluation V1/V2 evidence complete
V1 remains default
```

只有现有 `V2CutoverReadinessReport` 自己给出 READY，才能把 G11 标记为完成。即使 READY，本轮也不要开始 G12。
