# ModelRAG 2.0 G6 - Evidence-Centric QA

## Combined tasks: 2.0.13 Evidence Model + 2.0.14 Evidence Navigation + 2.0.15 QA V2

> Target runtime: Java 21  
> Prerequisite: G5 merged and green  
> Base commit reviewed: `9ed09255aa15b52eaaafaca68a0bb1b8ddbcc239`  
> Production default before G6: V1 QA / V1 Retrieval  
> G6 strategy: build an opt-in V2 evidence-centric QA path; do not make it the default yet  
> Flyway: no new migration required by default

---

## 1. Goal

G5 completed the V2 retrieval layer:

```text
Query
  ↓
HybridRetrievalService
  ↓
RetrievalCandidate
  ├── semantic V2
  └── lexical V2
  ↓
RRF / rerank
```

But a `RetrievalCandidate` is still only something search considers relevant. It is not yet verified, structured, citation-ready evidence suitable for answer generation.

G6 introduces:

```text
RetrievalCandidate
        ↓
EvidenceRetrievalService
        ↓
EvidenceExpansionService
        ↓
DocumentNode navigation
        ↓
EvidenceSelector
        ↓
EvidenceSet
        ↓
EvidenceSufficiencyPolicy
        ↓
EvidenceContextAssembler
        ↓
AnswerSynthesizer
        ↓
QaResult + node-level Citation
```

Hard invariant:

> Final V2 answers may only be generated from an `EvidenceSet`.

No V2 answer generator may directly consume `ScoredChunk`, `RetrievalCandidate`, raw Elasticsearch hits, or raw vector results.

---

## 2. G5 review result

G5 is accepted for the current baseline.

Verified:

- Semantic V2 reads `kb_vector_embedding`.
- Semantic SQL enforces active document version, active V2 IndexBuild, `IndexBuild.state=ACTIVE`, embedding profile, and soft-delete visibility.
- Semantic V2 uses pgvector HNSW iterative scan.
- Lexical V2 reads only `modelrag-retrieval-units-v2`.
- Active lexical build IDs come from PostgreSQL source of truth.
- active-build scope is bounded and overflow degrades instead of truncating silently.
- Elasticsearch hits are batch-validated through active `RetrievalUnit` reads.
- `RetrievalCandidate` is keyed by `retrievalUnitId`, not `chunkId`.
- RRF fusion preserves multiple retrieval units from the same node.
- V1 remains authoritative.
- V2 shadow comparison uses a bounded executor and document-level overlap.

Do not regress these properties.

## 3. Small G5 hardening before G6 logic

`RetrievalV2Request` currently has a hardcoded fallback profile:

```text
qwen3-v1
```

while V2 indexing already supports:

```text
modelrag.index.v2.embedding-profile
```

Under the default configuration these match, but a configured profile change could make V2 semantic shadow/QA appear empty.

Make production V2 callers explicitly use the configured profile.

Recommended:

```text
RetrievalV2QueryProperties
```

or:

```text
V2EmbeddingProfileProvider
```

Production callers that must pass it explicitly:

```text
RetrievalShadowComparator
QaV2ApplicationService
```

Keep the hardcoded request default only as a compatibility/test fallback if useful.

Add a test proving a non-default configured profile reaches semantic search.

## 8. Primary and expanded evidence

Each final `RetrievalCandidate` becomes a primary evidence seed.

Example:

```text
candidate unit=101 node=55
↓
Evidence E1
origin=RETRIEVAL
primary=true
retrievalUnitId=101
nodeId=55
```

Navigation can add:

```text
E2 origin=PREVIOUS
E3 origin=NEXT
E4 origin=PARENT
```

Structural evidence may have:

```text
retrievalUnitId = null
```

Do not invent a fake retrieval unit.

---

## 9. Candidate content vs node content

A `RetrievalUnit` may be a window, oversized-node split, or title-enriched projection.

Therefore primary evidence text should initially remain:

```text
candidate.content
```

while source identity is validated through the active `DocumentNode`.

Use the node for:

```text
active visibility
node type
page/char locator
structure
```

Do not blindly replace a split/window candidate with the entire potentially huge node content.

## 11. EvidenceExpansionService

Add:

```text
EvidenceExpansionService
```

All navigation must be bounded.

Initial policy:

```text
paragraph-like:
    previous 1
    next 1

TABLE:
    bounded TABLE_ROW children

SECTION:
    small bounded direct context only

REFERENCE:
    do not follow automatically in DIRECT_RAG G6
```

Reference traversal becomes more important in G7 Agentic Retrieval.

Recommended config:

```text
modelrag.qa.v2.max-primary-evidence=8
modelrag.qa.v2.max-expanded-evidence=16
modelrag.qa.v2.max-navigation-actions=24
modelrag.qa.v2.max-table-rows=20
modelrag.qa.v2.neighbor-radius=1
```

If the budget is exhausted, stop expansion and record a budget/degraded condition.

Never load the entire document.

## 12. Deduplication and ordering

Deduplicate structural evidence by:

```text
documentVersionId + nodeId
```

Primary evidence wins over an expanded duplicate.

Recommended ordering:

```text
E1 primary
E2 previous of E1
E3 next of E1
E4 primary
E5 table child of E4
```

Evidence IDs must be stable after final ordering.

## 14. EvidenceSufficiencyPolicy

Add:

```text
EvidenceSufficiencyPolicy
```

Return:

```text
EvidenceSufficiency
```

Recommended fields:

```text
sufficient
confidence
reason
coverage
```

No LLM sufficiency judge in G6.

Minimum deterministic rules:

```text
no primary evidence
→ insufficient

all candidates stale/dropped
→ insufficient

top evidence below configured threshold
→ insufficient

valid active evidence
→ potentially sufficient
```

For obvious multi-part queries such as:

```text
分别
各自
对比
A和B
```

require more coverage than a single-fact question when practical.

Do not treat RRF score as a calibrated probability; V2 confidence is a heuristic.

## 22. Failure/degradation behavior

Required:

```text
V2 retrieval empty
→ refuse

candidate source node stale
→ drop candidate; continue

neighbor navigation failure
→ keep primary evidence; mark degraded

document-name lookup failure
→ generic label; keep evidence

model unavailable/fails
→ EvidenceSet-only deterministic fallback

V2 catastrophic failure
→ fail safely/refuse
```

Do not hide a V2 failure by silently mixing in V1 evidence.

Operator rollback is the feature flag.

## 23. Required tests

### Evidence model

- candidate -> primary Evidence.
- stale candidate dropped.
- stable unique E1/E2 IDs.
- same expanded node deduplicated.
- primary wins expanded duplicate.
- EvidenceSet bounded.

### Navigation

- paragraph previous/next.
- table row cap.
- navigation-action budget.
- inactive-version node excluded.
- navigation failure preserves primary evidence.
- no whole-document load.

### Sufficiency

- zero evidence -> insufficient.
- valid strong evidence -> sufficient.
- stale-only -> insufficient.
- low evidence -> insufficient.
- multi-part query requires more coverage than simple fact.

### Context

- `[E#]` labels.
- document/title/page location.
- sanitization.
- token budget.
- evidence IDs survive truncation.
- no raw internal metadata dump.

### Citation

- V1 constructor/source compatibility.
- V2 documentVersionId/nodeId identity.
- retrievalUnitId/indexBuildId when available.
- citations only from selected primary Evidence.

### QA V2

- flag false = current V1.
- flag true = V2.
- insufficient evidence = zero model calls.
- sufficient evidence = exactly one model call.
- model failure = EvidenceSet-only fallback.
- node-level citations.
- common audit/event/conversation behavior preserved.

### G5 profile hardening

- a non-default configured V2 embedding profile reaches the semantic request.

## 24. Performance invariants

Online G6 cost must scale with:

```text
selected candidates
+
bounded navigation
```

not document/dataset/corpus size.

For TopK ~5 and radius 1, database rows should remain in the tens, not thousands/millions.

Avoid N+1 document metadata lookups.

Primary active-node lookup may be batched if clean:

```java
List<DocumentNode> findActiveByIds(long datasetId, Collection<Long> nodeIds);
```

If added, cap the batch size.

## 28. Acceptance criteria

G6 is complete only when:

1. Evidence/EvidenceSet domain exists.
2. final V2 answer generation accepts only EvidenceSet.
3. candidates are active-node validated.
4. stale candidates are dropped.
5. expansion is bounded.
6. no whole-document online load exists.
7. no legacy Chunk is used in V2 evidence flow.
8. deterministic sufficiency policy exists.
9. insufficient evidence invokes zero model calls.
10. EvidenceContext uses source-labelled `[E#]` blocks.
11. source path/page metadata is preserved.
12. final V2 synthesis occurs exactly once.
13. model fallback uses EvidenceSet only.
14. V1 Citation compatibility remains.
15. V2 Citation contains documentVersionId + nodeId.
16. `modelrag.qa.v2.enabled=false` by default.
17. V1 remains unchanged when disabled.
18. V2 is executable when enabled.
19. common audit/event/conversation behavior remains.
20. production V2 callers use the configured embedding profile.
21. no G7 Agent work starts.
22. V1-V60 remain untouched.
23. full Maven tests pass.
