# ModelRAG G10.1 — AI Compute Runtime Completion

> Java 21 / Python 3.11+  
> Base commit: `9ec42da70a12e55229fda835181a75c1de012f88`  
> Scope: finish G10 runtime operability before G11  
> No Flyway migration. Do not start G11.

## Review result

G10 has correctly established the Java/Python boundary:

- `modelrag-inference-client`
- `AiServiceClient`
- `RemoteEmbeddingProvider`
- `RemoteRerankProvider`
- `RemoteDocumentAiClient`
- `RemoteOcrClient`
- Java still owns embedding cache/batching/token/health policy
- Java still owns rerank fallback/degraded policy
- Java still owns ObjectStorage, parser routing, DocumentVersion and IndexBuild lifecycle

Preserve all of that.

The blocker is that `modelrag-ai-service` is not yet a runnable compute plane. The checked-in `app/engines/*` files provide only Protocol interfaces plus `Unavailable*Engine`, while production bootstrap uses `app = create_app()` without injecting engines. The checked-in Dockerfile therefore starts a service with no real embedding, rerank, document-AI or OCR implementation.

## P0 — production engine bootstrap

Add `app/engine_factory.py` or equivalent.

Production startup must be equivalent to:

```python
settings = Settings.from_env()
engines = build_engine_bundle(settings)
app = create_app(settings, engines)
```

Do not leave `app = create_app()` as the only production path.

Use explicit configuration for engine/model selection. Unknown or required-but-unavailable engine configuration must fail startup/readiness rather than silently using test/fake engines.

## P0 — concrete runtime engines

Add at least one actual runnable implementation for every advertised capability:

```text
EmbeddingEngine
RerankEngine
DocumentAiEngine
OcrEngine
```

Use real, verified Python libraries/APIs. Do not invent wrappers for packages whose APIs are not verified.

Heavy dependencies should live in optional runtime extras so normal unit tests do not download model weights.

### Embedding

Keep the hard contract:

```text
logical profile = Qwen3-Embedding-0.6B
dimensions = 1024
```

The physical model path/id may be configured separately. The engine must verify 1024 output dimensions and finite values. Never silently fall back to another model.

### Reranker

Use a real model-backed runtime engine. Preserve candidate IDs and return exactly one finite score for each candidate.

### Document AI

Add a concrete PDF/DOCX document engine that returns the existing `DocumentParseResponse` structure and preserves page/layout information where the chosen library provides it.

### OCR

Add a concrete OCR engine. `/v1/ocr` must execute real OCR, and Document AI may reuse the same OCR capability.

## P0 — runnable Docker/runtime profile

The current Dockerfile only installs FastAPI/Pydantic/Uvicorn. Add a production-capable runtime path.

Preferred options:

```text
Dockerfile installs .[runtime]
```

or:

```text
Dockerfile.runtime
```

If a lightweight API/test image remains, README must clearly distinguish it from the production-capable runtime image.

Acceptance: one checked-in documented runtime image must be able to become READY and execute actual compute without test-only fake injection.

## P0 — capability-aware readiness

Readiness should reflect enabled/required capabilities.

Example:

```json
{
  "status": "UP",
  "capabilities": {
    "embedding": "UP",
    "rerank": "UP",
    "document_ai": "DISABLED",
    "ocr": "DISABLED"
  }
}
```

Rules:

- required + unavailable => overall DOWN
- disabled => DISABLED, not DOWN
- required `Unavailable*Engine` can never report UP

## P1 — Java dependency boundary

Add a deterministic boundary guard for `modelrag-inference-client`.

Forbid dependencies on:

```text
modelrag-indexing
modelrag-search
modelrag-qa
modelrag-agent
modelrag-tool-gateway
modelrag-server
```

Use Maven Enforcer or equivalent.

Inspect the current `modelrag-api` dependency. Remove it if no inference-client source actually requires it.

## P1 — profile semantics

Document three distinct axes:

```text
physical Python model id/path
logical compute profile: Qwen3-Embedding-0.6B
V2 persisted index profile alias: qwen3-v1 (if retained)
```

Hard invariant:

```text
one persisted index profile alias must always resolve to the same logical model + dimensions
```

Changing the model/dimensions requires a new profile/build, not silent remapping.

## Tests

Add Python tests for:

- runtime engine factory
- unknown engine type fails
- required unavailable capability makes readiness DOWN
- disabled capability is DISABLED
- production bootstrap does not silently choose Fake engines
- engine load failure is visible

Add lightweight adapter tests around real engine classes; normal CI must not download large models.

Add an opt-in real runtime smoke test covering:

```text
/health/ready
/v1/embeddings
/v1/rerank
/v1/documents/parse
/v1/ocr
```

Embedding smoke must verify 1024 finite values.

If model/runtime dependencies are unavailable, report the integration test as NOT RUN with the exact reason.
