# ModelRAG 2.0 — G11.7 Retrieval Executor Capacity & Deadline-Aware Admission

## 0. 本轮定位

G11.6 已经把 PostgreSQL Vector Search 的核心瓶颈关闭：

```text
Vector Search p50: 3347ms → 23.855ms
Vector Search p95: 4152ms → 43.778ms
overall timeoutRate: 44.86% → 9.81%
degradedRate: 58.90% → 10.52%
```

当前剩余主要问题已经转移为：

```text
EXECUTOR_QUEUE_BOUND
```

尤其：

```text
Semantic queueWait p95 ≈ 805ms
Lexical C32 存在明显 queue wait
```

而实际执行本身已经较快：

```text
Embedding remote p50 ≈ 193ms
Vector Search p50 ≈ 24ms
Elasticsearch p50 ≈ 25ms
Active Validation p50 ≈ 5ms
```

本轮目标：

> 在不调大 800ms Channel Deadline、不降低 Benchmark 压力、不破坏下游资源的前提下，合理设计 Semantic / Lexical Executor Capacity（执行器容量）、Bounded Queue（有界队列）和 Deadline-Aware Admission（感知截止时间的准入），避免请求排队到 deadline 已经过期才开始执行。

## 6. P0：Deadline-Aware Admission

当前无效路径：

```text
请求进入 executor queue
↓
等待 600~800ms
↓
任务开始
↓
remaining deadline ≈ 0
↓
立即 timeout/degraded
```

新逻辑：

```text
channel deadline = submittedAt + 800ms

submit
↓
queue
↓
task start
↓
remaining = deadline - now
↓
如果 remaining < minimumUsefulBudget
    直接拒绝本 channel
    标记 *_ADMISSION_TIMEOUT
    不调用 Ollama / ES / PostgreSQL
否则继续
```

建议支持：

```text
SEMANTIC_ADMISSION_TIMEOUT
LEXICAL_ADMISSION_TIMEOUT
```

它们必须：

```text
timeout=true
degraded=true
```

并与执行中 timeout 区分。

---

## 7. P0：有界 Queue

如果现有 executor 使用无界或过大的队列，改成 bounded queue。

队列满时：

```text
SEMANTIC_REJECTED
LEXICAL_REJECTED
```

语义：

```text
degraded=true
timeout=false
```

如果是因为排队后 deadline 已耗尽，则：

```text
*_ADMISSION_TIMEOUT
timeout=true
```

两者不要混淆。


## 9. Downstream Concurrency Guard

Executor worker 多，不代表下游可以无限并发。

检查：

```text
AiServiceClient maxConcurrentRequests
Hikari maximumPoolSize
ES HTTP capacity
```

不要重复造多层 Semaphore，除非现有 concurrency 控制明显失配。

必须确保：

```text
semantic DB concurrency
+ lexical validation concurrency
+ application DB usage
< Hikari pool capacity
```

---

## 10. P1：Queue Time Budget

可引入：

```text
maxQueueWaitMs
```

如果 queueWait 超过合理预算：

```text
不再执行
→ *_ADMISSION_TIMEOUT
```

这样避免：

```text
已经排了 700ms
还继续做 200ms embedding
```

具体数值必须通过容量实验选择，不能拍脑袋。

## 11. 必须新增/更新的测试

### 11.1 Admission Timeout

模拟 queue wait 接近 deadline。

断言：

```text
remaining budget 不足
→ 不调用 downstream
→ SEMANTIC_ADMISSION_TIMEOUT / LEXICAL_ADMISSION_TIMEOUT
→ timeout=true
→ degraded=true
```

### 11.2 Rejection

队列满触发 `RejectedExecutionException`：

```text
SEMANTIC_REJECTED / LEXICAL_REJECTED
degraded=true
timeout=false
```

### 11.3 Queue Metrics

断言：

```text
channelMs >= queueWaitMs
channelMs >= executionMs
```

Semantic：

```text
executionMs >= embeddingMs
executionMs >= vectorSearchMs
```

允许 measurement overhead，不做严格毫秒求和。

### 11.4 Warmup Separation

Warmup 不进入 measured aggregate。

### 11.5 Executor Saturation

验证：

```text
workers 全忙
queue 有界
不会无限堆积
不会死锁
不会 CallerRuns 阻塞请求线程
```

### 11.6 Existing Correctness

必须继续保持：

```text
ANN-first
bounded refill
DB statement timeout
stale build exclusion
sentinel recall
valid evidence
bounded results
dataset isolation
```
