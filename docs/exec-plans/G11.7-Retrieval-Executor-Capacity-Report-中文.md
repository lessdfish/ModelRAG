## 7. Chosen Configuration

- Semantic workers: 8
- Semantic queue capacity: 32，bounded
- Lexical workers: 8
- Lexical queue capacity: 32，bounded
- Rejection policy: `AbortPolicy`
- Channel timeout: 800ms，未调大

### Why This Capacity

4 workers 下仍有大量请求接近 admission deadline。8 workers 是三个实验档位中，能够显著降低 queue wait、timeout 和 admission timeout 的最小配置。

同时满足 downstream capacity guard：

- Semantic 与 Lexical 最大 DB 消费者合计为 16，小于 HikariCP 20，保留 4 个连接余量。
- Semantic workers 8 小于 inference semaphore 32。
- 未继续扩大至 16/32 workers，避免无限扩容并放大 Ollama、PostgreSQL 和 Elasticsearch 争用。
