## 4. Checkpoint B — Million-unit load test

Create a deterministic benchmark workspace:

```text
benchmarks/retrieval-scale/
├── README.md
├── generate/
├── workloads/
├── run/
└── reports/
```

Two explicit modes:

```text
smoke: 10k-50k retrieval units
full:  >=1,000,000 ACTIVE retrieval units
```

Full topology:

```text
>= 20,000 active documents
>= 1,000,000 active RetrievalUnits
1024-d vectors
additional stale/superseded units
shared modelrag-retrieval-units-v2 ES index
multiple IndexBuild generations on a subset of docs
```

The active document count must exceed `modelrag.retrieval.v2.max-active-build-filter` so the benchmark exercises the hard path rather than only the easy case.

Synthetic deterministic vectors are allowed in benchmark scope. Do not generate one million embeddings through the model service just to benchmark retrieval.

Load data with streaming/batching. Never hold 1M x 1024 vectors in JVM heap.

### Workloads

Run:

```text
semantic-only
lexical-only
hybrid
document-scoped
broad dataset
high active-build-count
stale-build exclusion
```

Concurrency:

```text
1
8
32
```

Collect where available:

```text
throughput
p50/p95/p99
error/degraded/timeout rate
semantic/lexical/fusion/rerank latency
candidate counts
DB connections
JVM heap / GC
ES latency
```

Capture `EXPLAIN (ANALYZE, BUFFERS)` for representative semantic queries.

Hard correctness gates:

```text
no stale-build leakage
no cross-dataset leakage
no silent active-build truncation
bounded results
bounded memory
```

Do not hide a scalability bug by reducing the dataset size.

Write machine-readable and human-readable reports with commit, versions, hardware, dataset shape, concurrency, warmup, duration and all measurements.

The full run is opt-in. If the environment cannot execute it, report `NOT RUN` with the exact reason. Never call a 10k run a million-unit result.

## 5. Checkpoint C — Canonical V1/V2 evaluation

The current evaluator is chunk-centric (`expectedChunkIds`). Do not compare V1 chunk IDs directly to V2 retrieval-unit IDs.

### V66 labels

Add to the existing evaluation dataset as additive fields:

```text
expected_document_ids JSONB NOT NULL DEFAULT '[]'
expected_node_ids JSONB NOT NULL DEFAULT '[]'
expected_evidence_groups JSONB NOT NULL DEFAULT '[]'
```

Keep legacy `expected_chunks`.

Do not fabricate node IDs from old chunks during migration.

Legacy-only cases may be marked:

```text
LEGACY_LABEL_ONLY
```

### Evidence groups

Support required evidence groups for cross-document/multi-hop cases:

```json
[
  {"name":"fact-a","documentIds":[10],"nodeIds":[101,102]},
  {"name":"fact-b","documentIds":[11],"nodeIds":[201]}
]
```

A group is satisfied if one accepted evidence item is found. `Complete Evidence Recall` requires all required groups.

### Categories

Use bounded categories:

```text
POINT_FACT
CROSS_SECTION
CROSS_DOCUMENT
MULTI_HOP
WHOLE_DOCUMENT
GLOBAL
TABLE
VERSION_SENSITIVE
REFERENCE
REFUSAL
```

Report sample counts and per-category metrics. Mark underrepresented categories `INSUFFICIENT_SAMPLE`.

### Refactor evaluator

Do not keep expanding the already-large `EvalController`.

Extract services such as:

```text
EvaluationRunner
EvaluationLabelResolver
V1EvaluationAdapter
V2EvaluationAdapter
EvaluationMetrics
CutoverReadinessEvaluator
```

Keep existing APIs compatible where practical.

### V1 adapter

Use the current production V1 path and capture:

```text
chunk IDs
resolved document IDs
latency
degraded components
answer/refusal
context
tokens where available
```

Do not modify V1 ranking for the evaluation.

### V2 adapter

Use the actual V2 retrieval/evidence path and capture:

```text
document IDs
documentVersion IDs
node IDs
retrievalUnit IDs
semantic/lexical/fused ranks
selected evidence
navigation actions
latency
degraded components
answer/refusal
```

Online shadow document overlap is telemetry only, not the quality gate.

### Metrics

At minimum:

```text
Document Recall@5 / @20
Document MRR
Document nDCG
Node Recall@K where labels exist
Complete Evidence Recall
Evidence precision

answer accuracy
faithfulness
answer relevance
refusal precision
refusal recall
refusal accuracy

p50/p95/p99
error rate
degraded rate
retrieval action count
navigation action count
token usage where available
```

Mark each metric:

```text
COMPARABLE
V1_ONLY
V2_ONLY
INSUFFICIENT_LABELS
```

Never convert missing labels to fake zero scores.
